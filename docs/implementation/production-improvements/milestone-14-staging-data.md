# Milestone 14: Production-like relational staging data

## Status: partially implemented

### Delivered in this increment

- Audited the current migration/model/factory/seeder footprint and documented important actual key types, logical links, unique constraints, soft deletion, and schema gaps.
- Hardened production/local administrator bootstrap to preserve existing passwords and refuse soft-deleted, non-admin, inactive, or unassigned accounts rather than silently granting Super Admin.
- Hardened local role/demo accounts so reruns preserve existing credentials and refuse unowned account collisions or new role assignments.
- Added opt-in Small/Standard/Large target profiles, fixed seed/reference-date context, exact database-name/host and cache isolation checks, explicit integration-isolation gates, and separate private staff/customer password requirements. Large profile checks PHP memory, local disk space, and requires operator confirmation of database capacity.
- Added manifest and per-record ownership tables, dataset-locked RBAC/staff/customer/profile/device generation, read-only status, and machine-readable ownership validation for those generated relationships.
- Added bilingual genre and catalog generation, genre mappings, and correctly linked series/season/episode trees. Catalog content is explicitly draft/unpublished and has no media asset, avoiding false playable or licensed claims. Catalog records use registry-stored UUIDs because the final entertainment/episode schema does not have slug columns.
- Added 2,000 fictional actor/director profiles and 4,600 ownership-tracked title credits to the verified Standard catalog. Credits are shared across productions; cast profiles have no fabricated images or external identities.
- Added deterministic licensing windows and territory rules for staging entertainment. The Standard dataset has 1,035 date windows and 1,701 country restrictions, including expired and future windows; integrity checks verify each policy maps to an owned title.
- Added a bounded actual media fixture generator (5/25/50 for Small/Standard/Large, maximum 50). It creates test-pattern H.264/AAC MP4 sources, FFprobe-derived metadata and measured checksum/size, HLS 360p/720p and audio renditions, DASH, poster, preview, and VTT/SRT tracks under private dataset-scoped storage. Asset, track, processing-record and catalog-link ownership are registered; media readiness checks the actual files. Titles remain unpublished and playback authorization is unchanged.
- Added bilingual staging editorial generation with 150 Standard articles, unique dataset-scoped slugs, varied instructional topics, drafts and published dates, and validated English/Bengali fields. The generated prose avoids unverified religious quotations, rulings and historical assertions. View counts are deterministic simulation estimates, not observed analytics.
- Added dataset-scoped subscription coupons with active, expired, scheduled and inactive cases, redemption limits, and eligible-plan mappings. Coupon rows and pivot rows are owned and validated together; no coupon redemption or payment fulfillment is fabricated.
- Added bounded historical search events for owned customer/profile pairs. Queries use the generated localized catalog names, deterministic account-relative timestamps, and valid `movie`/`tvshow` types; `search_id` stays null because no clicked result is represented. Each row has an ownership record and is covered by integrity validation.
- Added staging-only Meilisearch synchronization under a reserved, dataset-derived index UID. It indexes only owned catalog documents with English/Bengali metadata and dataset/publication/type/genre filters, waits for task completion, runs bilingual and faceted queries, and registers search-document ownership. It never lists, deletes, or writes the default/live index.
- Added historical customer-support tickets across supported categories, priorities and lifecycle states. Tickets are assigned only to owned customer-support staff; internal notes have owned staff authors and stable ownership keys. No customer messages are sent, and reruns verify existing ticket/note ownership instead of duplicating rows.
- Added synthetic marketing consent choices and campaign workflows. Consent records cover email and push opt-in/opt-out. Campaigns are generated as drafts, pending review, approved with independent maker-checker identities, or rejected; they remain unpublished with no delivery rows, messages, or push requests.
- Added database-backed in-app notification history with deterministic UUIDs, generated customer recipients, historical read/unread and archive states, and ownership validation. This path inserts rows only and never invokes Laravel notification dispatch, mail, or push.
- Added synthetic historical operations incidents assigned to generated technical-operations staff, plus audit events marked `staging.fixture.generated` that reference dataset-owned records. Incident creation bypasses alert-producing application actions; the fixtures do not report live service health.
- Added owned, ready analytics report snapshots for audience, subscription, content, revenue and playback groups. Content analytics now also derives ended-session count, watch hours, completion rate against measured media runtime, and UUID-safe popular playback titles from actual playback sessions. Diagnostic quality metrics remain empty unless clients emit telemetry.
- Added owned revision snapshots for internal content review using active staging editors/managers and independent content reviewers. Submission histories include pending, approved and rejected states, but do not mutate catalog publication state or create workflow audit side effects.
- Added dataset-owned bilingual Live TV categories and channel drafts with deterministic UUIDs. Channels stay unpublished and have no stream mappings because no verified, locally playable live source is configured.
- Added dataset-owned standalone video drafts with meaningful bilingual metadata and unique fixture slugs. They remain unpublished with no URL or stream mapping until a real test asset is attached.
- Added the admin content publication service as a shared workflow boundary, then added staging-only publication for approved free movies with ready private media, artwork, and an active Bangladesh license. Playback-enabled profiles guarantee one eligible approved title. Historical ended sessions link owned active customers, devices, adult profiles and published media; duration never exceeds FFprobe-measured media runtime. Sanctum rows are hash-only with empty abilities, and no bearer credential is created.
- Added dataset-owned staging plans and plan-limitation mappings, customer subscription lifecycle rows, and synthetic BDT paid/failed transaction attempts. Attempts are recorded only in the legacy subscription transaction table; no provider calls, verified-payment rows, or fulfillment paths are used. Customer subscription flags are synchronized from current active staging subscriptions.
- Extended relational validation to plans, plan mappings, subscriptions and synthetic transactions. Added a composite ownership index so the Standard dataset's transaction checks complete efficiently. Added a feature test for generation, stable reruns, ownership counts, and validator results.
- Corrected local demo staff `user_type` seeding and aligned the livestream fixture test with its playable demo fixture.
- Added focused configuration and determinism tests.

Customer watchlists, bilingual reviews, and watch-history events now use the UUID-compatible legacy columns and ownership validation. Playback generation now has one positive reduced Small-profile run and an idempotent rerun; Standard-scale playback and duration/memory benchmarking remain pending. Isolated search sync and playback-session analytics are verified at reduced scale, while Standard-scale indexing, safe reset, peak-memory and Standard-storage benchmarks, browser checks, and analytics accuracy outside the playback-session subset remain pending. The seeder command reports the manifest as `partial` and warns which configured targets remain ungenerated. Large profile is not verified. The latest customer engagement and continue-watching code slices have not been test-executed per the user instruction; PHP syntax checks and `git diff --check` were run. No CI/CD or Flutter work is included.
